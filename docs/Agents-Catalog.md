## What is an Agent?

An agent is an AI orchestrator that fulfils a complete user goal by composing and sequencing one or more skills. Where a skill does one thing, an agent handles an end-to-end workflow — deciding which skills to call, in what order, passing outputs between them, and returning a coherent result to the PM.

## Agent Definitions

---

### AG-01 — Feedback Agent

**Purpose**
Processes all incoming customer feedback: classifies sentiment and clusters into named themes using deterministic keyword matching — with zero hallucination. Returns themes, counts, and verbatim evidence snippets without saving anything until the PM approves.

**Triggered By**
- PM clicks "Analyse Feedback" in the Feedback Hub

**Workflow**

```
1. Read all feedback_items from DB for the product area
        ↓
2. SK-03 — Sentiment Classification (per item)
        ↓
3. SK-01 — Keyword-Based Theme Detection (per item)
   → Returns ThemeMatch[]: { name, snippet }
        ↓
4. Aggregate: themeCountMap, themeEvidenceMap
        ↓
5. Return: { themes, themeCounts, themeEvidence, feedbackCount, preview }
   (nothing saved yet)
```

**Outputs**
| Output | Consumed By |
|---|---|
| themes[] | AG-02 (Pipeline Agent) via Pipeline Approval Modal |
| themeCounts[] | Pipeline Approval Modal display |
| themeEvidence[] | Pipeline Approval Modal — shown under each theme |
| preview | Pre-expanded sections in the modal |

**Key Constraint**
`themeEvidence[i]` is the actual sentence from a real feedback item that contained the matched keyword. It is never generated by an LLM.

### AG-02 — Pipeline Agent

**Purpose**
Receives approved themes from the PM and runs the full artefact generation pipeline via SSE, creating all PM deliverables in one action.

**Triggered By**
- PM clicks "Approve & Create All" in the Pipeline Approval Modal

**Workflow**

```
Receive: { themes, themeCounts, feedbackCount, prdTitle, sprintName }
        ↓
SK-04 — Store Themes → feedback_themes table
        ↓
SK-05 — Create Opportunities (summaries per theme)
        ↓
SK-06 — Generate PRD → documents table (type: PRD)
        ↓
SK-07 — Generate User Stories → documents table (type: UserStory)
        ↓
SK-08 — Generate Acceptance Criteria → documents table (type: AcceptanceCriteria)
        ↓
Create Roadmap items linked to themes
        ↓
Create Sprint with name + goal
        ↓
Create Sprint Tickets
        ↓
Emit SSE 'done' event → client auto-closes modal
```

**SSE Progress Events**
Each step emits `{ step: string, message: string }` so the PM sees real-time progress.

**Agent Running Visibility**
When the PM approves the pipeline, `PipelineApprovalModal.tsx` calls `setAgentRunning('Feedback Pipeline')` via `AgentStatusContext`. This causes the Documents tab to immediately show a yellow "Feedback Pipeline running…" banner. The banner clears automatically via `clearAgentRunning()` when the SSE stream completes (success or error).

**PRD Auto-Draft**
When the pipeline creates roadmap items with status `planned`, the `roadmap-planned-check` polling query in `DocumentWorkspace.tsx` detects them and shows a "Agent drafting PRD · please wait…" banner until the PRD draft document appears in the document list.

### AG-03 — Insight Agent

**Purpose**
Transforms synthesised feedback themes into written insight summaries and answers the PM's plain-language questions about customer data.

**Triggered By**
- Insights page load (auto-generates summary per theme)
- PM submits a question in the "Ask AI" input

**Workflow — Summary path**
```
SK-09 — Data-Backed Insight Summary
  Input: theme name, count, evidence snippet
  Output: written narrative for the insight card
```

**Workflow — Q&A path**
```
SK-10 — Natural Language Feedback Q&A
  Input: PM's question, current themes with data
  Output: grounded answer with citations
```

---

### AG-04 — Document Agent

**Purpose**
Manages the full document lifecycle: AI generation from feedback, inline editing with automatic versioning, version restore, and an AI assistant that can update documents using attached reference files.

**Triggered By**
- PM selects theme + doc type → clicks "Generate"
- PM clicks Edit → edits → clicks Save
- PM clicks History → Restore
- PM uploads a file via 📎 → asks AI a question

**Workflow — Generate**
```
SK-11 — Document Generation from Feedback
  Input: theme name, doc type, feedback context
  Output: PRD / UserStory / AcceptanceCriteria document
```

**Workflow — Edit & Save**
```
PM edits in textarea → clicks Save
        ↓
SK-12 — Document Version Snapshot
  Backend: INSERT current sections → document_versions
  Backend: UPDATE documents SET sections = newContent
  Frontend: parse sections string → show updated <pre>
```

**Workflow — AI Assistant**
```
PM attaches Reference doc via 📎 → PM asks question
        ↓
SK-13 — Document AI Q&A
  Input: PM question, active doc content, attached Reference doc content
  Output: streamed answer (SSE) — may include updated PRD content
```

### AG-05 — Roadmap Agent

**Purpose**
Links roadmap items to customer evidence and supports roadmap management.

**Triggered By**
- Pipeline Agent creates roadmap items automatically
- PM manually creates or edits a roadmap item

**Workflow**
```
SK-14 — Roadmap Justification Generation
  Input: roadmap item, linked theme, evidence
  Output: leadership-ready justification narrative
```

---

### AG-06 — Sprint Agent

**Purpose**
Converts prioritised roadmap items into sprint-ready user stories, manages multi-sprint planning, and runs grooming checks.

**Triggered By**
- PM clicks "→ Sprint" on a roadmap item
- PM creates, renames, or moves tickets between sprints

**Workflow — Ticket generation**
```
SK-15 — Sprint Ticket Generation
  Input: roadmap item, linked theme
  Output: ticket title, description, story points

SK-16 — Acceptance Criteria Generation (within SK-15)
  Output: 3 testable criteria (JSON array)

SK-17 — Backlog Grooming Detection (rule-based, no LLM)
  Flags: missing AC | story_points > 13 | needs_grooming = true
```

---

### AG-07 — Sprint Brief Agent

**Purpose**
Reads actual sprint ticket data and generates a complete sprint brief streamed in real time.

**Triggered By**
- PM clicks "Sprint Brief" in the Sprint Planner header

**Workflow**
```
Query sprint metadata + all sprint_tickets
        ↓
SK-18 — Sprint Brief Generation (streaming)
  Compute: totalPoints, done/in_progress/todo counts, risks
  Build: markdown brief with real ticket data
  Stream: SSE chunks to client
```

---

### AG-08 — Knowledge Agent

**Purpose**
Answers PM questions grounded in documents stored in the Knowledge Base.

**Triggered By**
- PM submits a question in the Knowledge Base search input

**Workflow**
```
SK-19 — Knowledge Base Q&A
  Input: PM question, document excerpts
  Output: grounded answer with source citations
```

---

### AG-09 — Triage Agent

**Purpose**
Runs pre-configured triage tasks on all current feedback in the system. Available from the Agent Center page. Provides a quick way for PMs to re-classify sentiment and themes without going through the full pipeline approval flow.

**Triggered By**
- PM clicks "Run" on a triage agent card in Agent Center

**Agent Running Visibility**
`AgentCenter.tsx` calls `setAgentRunning(agent.label)` before the API call and `clearAgentRunning()` in the `finally` block. The Documents tab shows a yellow banner for the duration.
